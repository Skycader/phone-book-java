📋 Шпаргалка по командам Gradle

Команда

Что делает (коротко)

Когда использовать

**`gradlew clean`**

Удаляет папку  `build`

Если всё заглючило или хочешь собрать «с чистого листа».

**`gradlew build`**

Компилирует код и прогоняет тесты

Когда хочешь проверить, нет ли ошибок в коде.

**`gradlew clean build`**

Полная пересборка проекта

**Лучшая практика**  перед тем, как отдавать проект кому-то другому.

**`gradlew run`**

Собирает и  **сразу запускает**

Чтобы быстро потестить изменения, не выходя из консоли.

**`gradlew jar`**

Делает один  `.jar`  файл

Когда нужен результат сборки (лежит в  `build/libs`).

**`gradlew installDist`**

Создает папку с батником и либами

Когда хочешь получить  **готовую папку**  с программой для юзера.

----------

🔍 Подробности (зачем и куда смотреть)

-   **`gradlew run`**  
    Чтобы работало, в  `build.gradle`  должен быть  `id 'application'`. Удобно, если твой батник из начала разговора — это просто обертка над этой командой.
-   **`gradlew installDist`**  
    После этой команды ищи результат в:  `build/install/[название_проекта]/`. Там будет папка  `bin`  (в ней готовый  `.bat`) и  `lib`  (там все JAR-ники, включая твой и библиотеки типа ORMLite). Это  **самый надежный**  способ деплоя.
-   **`gradlew tasks`**  
    Если забыл, какие вообще команды есть в твоем проекте — вбей это, и Gradle вывалит весь список доступных задач.

----------

💡 Лайфхак для Java-разраба

Если тебе надоело таскать за собой папку  `lib`, поищи плагин  **ShadowJar**  (Fat Jar). Он позволяет делать команду  `gradlew shadowJar`, которая сваливает всё в один-единственный тяжелый файл  `.jar`, которому не нужны сторонние либы для запуска.
